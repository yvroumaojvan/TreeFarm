# 树场机制 v4.6.0（思维树的可选子技能）

## 触发规则（状态机，默认关闭，绝不自动触发）
- 用户说「开启思维树」→ 只开启思维树插件，本技能仍关闭
- 用户**再说**「开启深度思考模式」→ 本技能启动（本次会话内有效）
- 等价触发词：开启深度代码分析 / 开启深度代码阅读
- 关闭方式：用户说「关闭深度思考模式」/ 新会话自动回到关闭
- **衔接自动检测**（思维树 v3.1 功能）：思维树已开启、且任务是**大项目深度代码分析**（读全项目/改跨模块代码/找深层 bug）时，AI 可主动建议：「这个项目比较大，要不要顺便开启深度思考模式（树场）？可以省很多 token」——同样**只建议、不擅自开启**，用户拒绝就正常干活

## 本地工具（有终端环境的 agent 用，如 Claude Code / Qwen Code / Cursor / Gemini CLI）
`scripts/tree_farm.py`（纯 Python 标准库，零依赖，v4.6.0；已拆分为 `scripts/treefarm/` 多模块包，入口用法不变）：

### 核心功能（原版）
- `python3 tree_farm.py <项目> --brief [--compact]` → **AI 工作简报**（先读它，别全读项目；--compact 更省输出 token；加 `--json` 输出机器可读数据）
- `--genes <文件>` → 小树视角：某文件的正/反向基因（重构看正向，修 bug 看反向）
- `--bird <源文件> <目标>` → 报小鸟（强耦合，小虫子静态验证真伪）
- `--bird-weak <源文件> <目标>` → 报小鸟（弱耦合，双分支确认）
- `--analyze <文件>` → LLM 自动找小鸟（自动识别 API：<项目>/.treefarm.toml|.json → ~/.treefarm.toml|.json → 环境变量；找不到就 dry-run 预览）
- `--llm on/off/status` → LLM 开关（**默认开启**）
- `--search <关键词>` → 语义搜索（符号精确 + 标识符归一化 + 预构建内容索引，跨语言）
- `--trash` → 垃圾箱状态 | `--fix <文件>` → 修复协议（需用户同意）
- `--next-round` / `--converge` → 轮次与收敛控制
- `--db` → 存储状态（SQLite）| 任意命令加 `--debug` 看日志 | `--quiet` 关进度条

### 代码分析（原版 v3.1/v3.3，中文/英文命令等价）
- `--dead-code` / `分析 死代码` → 💀 死代码检测（从未被调用的函数/类，支持 Python/JS/Java/Go）
- `--circular-deps` / `分析 循环依赖` → 🔄 循环依赖检测
- `--impact <文件> [符号] [深度]` / `分析 影响 <文件>` → 💥 影响分析（改这里会影响哪）
- `--complexity [文件]` / `分析 复杂度` → 📊 圈复杂度（单文件或全项目，支持 Python/JS/Java/Go）
- `--architecture` / `分析 架构` → 🏗️ 架构分层识别（表现/业务/数据/工具层）
- `--debt` / `分析 技术债务` → 📉 技术债务评估（死代码/复杂度/重复/循环依赖四维打分）
- `--graph [文件]` / `分析 调用图` → 🕸 调用图（Mermaid flowchart；加 `--json` 输出结构化数据）
- `--duplicates [阈值]` / `分析 重复代码` → 🔁 重复代码检测（n-gram 相似度）
- `--duplicates-func [阈值]` / `分析 函数级查重` → 🔁 函数级重复代码检测（比文件级更精确）

### v4.4 扩展功能（新增）
- `--security` / `分析 安全` → 🔒 安全漏洞检测（SQL注入/XSS/命令注入/路径遍历/硬编码密码/不安全反序列化/弱哈希/时序攻击/ReDoS/CRLF注入/临时文件竞争/不安全随机数/SSRF/XXE/Zip Slip等20+种）
- `--performance` / `分析 性能` → ⚡ 性能问题检测（O(n²)算法/内存泄漏/递归爆炸/资源泄漏/字符串拼接循环/N+1查询等）
- `--logic` / `分析 逻辑` → 🧩 逻辑错误检测（比较运算符错误/边界条件/可变默认参数/除零风险/未初始化变量/竞态条件/类型混淆等，竞态条件仅在多线程环境下检测，减少误报）
- `--all-checks` / `分析 全部` → 🚀 全量检测（安全+性能+逻辑+死代码+循环依赖+复杂度+架构+技术债务，一键全面分析）
- `--sandbox on/off/status/run/test/trace/cov` → 🧪 沙箱动态测试（安全沙箱中执行代码，自动多输入生成器生成30组测试输入：边界值/恶意payload/极端参数，触发埋藏的休眠bug）
- `--static-ast` → 🔬 轻量AST辅助分析（默认关闭，开启后检测：AST沙箱绕过/动态代码执行/装饰器注册函数/类型混淆，作为静态分析的补充）

### v4.5 升级（性能/逻辑检测 AST 精确重写）
- `--performance` / `--logic` 从「正则堆砌」重写为 **AST 单遍精确检测**：同一文件只遍历一次，规则基于真实语法树节点，不再靠正则猜
- **性能检测**：循环内字符串拼接（`+=`/`s=s+'x'`/`str()`）、循环内线性查找（`in list`/`.index`/`.count`）、循环内 `re.compile`、N+1 查询（`.execute`/`.query`/`.filter`）、递归无终止、递归无缓存
- **逻辑检测**：可变默认参数、除零风险、边界条件（`for i in range(len(x))` 内 `x[i±1]`）、竞态（仅真实多线程 + 无锁自增）、TOCTOU（`if os.path.exists` 分支）、`is` 比较字面量、字符串大小比较
- **误报大幅下降**：删掉静态证明不了只会刷误报的规则（内存泄漏/类型混淆/`if x=y`）；`x += 1` 整数累加不再误报字符串拼接、`range(len(x)-1)` 正确代码不再误报 off-by-one
- **沙箱修复**：subprocess 路径补代码级黑名单防护（此前无防护）、覆盖率改用 AST 可执行行号精确统计（不再把空行/注释算进总行）、`mod` 别名修正为取模、进程退出瞬间 `/proc` 消失不再刷异常堆栈

### v4.6 升级（安全/性能规则补齐 + 路径友好）
- **安全检测扩到前端**：扫描范围从 `.py` 扩展到 `.js/.jsx/.ts/.tsx/.html/.htm/.vue`
- **新增 XXE 检测**：`etree/ET/ElementTree/lxml/minidom/sax/expat` 无防护解析 XML 外部实体注入
- **新增开放重定向检测**：`redirect(...)`/`Location` 头目标来自 `request`/`args`/`form`/`params`/`next` 等用户输入
- **新增认证绕过检测**：含敏感操作/后台/支付路径的路由，全文件无认证装饰器（`login_required`/`auth`/`jwt_required` 等）时提示未授权访问风险
- **XSS 规则扩充**：`innerHTML`/`outerHTML`/`document.write`/`insertAdjacentHTML`/Vue `v-html`/React `dangerouslySetInnerHTML`/Jinja2 `|safe`
- **新增资源泄漏检测**（性能）：函数内 `open()`/`socket.socket()` 绑定变量既不在 `with` 中、函数内也无 `.close()` → 文件句柄/连接泄漏
- **路径不存在友好提示**：CLI 输入错误路径给出 ❌ + 💡 提示，不再静默退出或抛 Traceback
- **测试 257 → 279 全绿**（新增 22 项：XXE/开放重定向/认证绕过/前端XSS/资源泄漏正反例/路径提示/restricted 多语言回归）

### 首次运行与增量更新
首次运行自动建基因库（`.tree_farm/tree_farm.db`，旧版 JSON 自动迁移），之后**真增量更新**：
改文件只重扫该文件；删文件级联回收引用基因；重命名（内容指纹）自动迁移基因并重扫引用方。
单文件检测支持：传入单个.py文件时自动使用所在目录或临时目录，不会报错。

## 工作流（AI 与 tree_farm.py 协作协议）
1. **启动**：`--brief` 读简报（大树清单 + 每文件正/反向基因 + 杂草索引 + 垃圾箱）
   → **读完简报不要全读项目**，按简报挑重点
2. **排查**：展开重点文件，发现可疑耦合 → 报小鸟（强/弱耦合分开报）
3. **验证**：小虫子（静态工具）验证 → 真→入库 / 假→吃掉；同一文件**最近 3 次验证 ≥2 次失败** → 进垃圾箱（滑动窗口熔断）
4. **收敛**：每轮结束 `--converge`；本轮新增小鸟 ≤2 只 = 收敛
5. **垃圾箱**：不清空 = 任务未完成；`--fix` 出修复协议
6. **修复**：结果报告用户，**用户同意后才允许修复代码**（默认逐处确认）

### v4.4 扩展工作流（安全/性能/逻辑深度分析）
当用户需要深度代码审查时：
1. `--all-checks` 一键全量检测，获取安全/性能/逻辑/代码质量综合报告
2. 针对高风险问题（🔴严重/🟠高危），展开对应文件查看详情
3. 安全漏洞优先修复，可能导致服务器被入侵
4. 性能问题在数据量大时才明显，小项目可忽略
5. 如需运行时验证，用 `--sandbox` 开启沙箱动态测试，自动生成输入触发bug
6. 如需深度语法树分析，用 `--static-ast` 开启AST辅助分析

## 关键机制速查
| 机制 | 说明 |
|---|---|
| 杂草模糊化 | 配置/资源/文档只存路径+大小+首行摘要，命中才展开 |
| 基因提取 | AST 扫 import 得强耦合种子（免费、100% 确定） |
| **函数级分析** | AST 跨文件 call/inherit 基因（v3 新增，Python） |
| 小虫子验证 | 静态工具查「真引用」→ 0 token 终审 |
| 腐肉检测 | mtime + 内容指纹增量重验，代码变了自动啃过期基因 |
| **删除级联** | 文件删除 → source+target+模块名引用全回收（v3） |
| **重命名检测** | 内容指纹匹配，自动迁移基因 + 重扫引用方（v3） |
| 小树过滤 | 按文件过滤相关基因，双向（重构看正向 / 修 bug 看反向） |
| 垃圾箱熔断器 | 最近 3 次验证 ≥2 次失败丢垃圾箱，最后专项修复（负反馈） |
| 收敛 | 一轮小鸟 ≤2 = 结束 |
| 存储 | SQLite（原子事务/WAL），旧 JSON 自动迁移并留 .bak |
| **代码分析** | 死代码 / 循环依赖 / 影响分析 / 复杂度 / 架构分层（v3.1，中文命令 `分析 X`） |
| **v4安全检测** | 20+种安全漏洞检测（SQL注入/XSS/命令注入/路径遍历/硬编码/反序列化/弱哈希等） |
| **v4性能检测** | O(n²)/内存泄漏/资源泄漏/字符串拼接循环/N+1查询等 |
| **v4逻辑检测** | 比较错误/边界条件/可变默认参数/除零/未初始化/竞态条件（仅多线程）/类型混淆 |
| **v4沙箱动态测试** | 安全沙箱执行代码，自动多输入生成器（边界值/恶意payload/极端参数） |
| **v4 AST辅助分析** | 轻量AST扫描（沙箱绕过/动态执行/装饰器注册/类型混淆），默认关闭 |

## 纯聊天 AI（无终端，如 ChatGPT / 豆包 / Kimi / DeepSeek）
没有本地脚本，用「纯提示词版.md」——把树场翻译成对话级协议：
先列项目清单（只列摘要不读全文）→ 边读边记依赖（会话内复用）→ 按需展开 → 可疑关联先找代码证据再下结论 → 同一区域反复判断失误先跳过最后专项处理 → 一轮无新发现即收敛 → 修复需用户同意。

v4扩展：安全/性能/逻辑分析时，先扫描代码模式（SQL拼接/eval/os.system/嵌套循环等），发现问题后给出中文解释和修复建议，高风险问题优先提醒。
