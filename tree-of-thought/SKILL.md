# 🌳 TreeOfThought 思维树（通用版）

> 思维树把「深度思考」变成一棵看得见的树：问题 = 树干，推理路径 = 分支，
> 每轮分支收拢成「共识」= 树的新芽，最终答案 = 果实。
> 本项目由 Operit 平台 TreeOfThought 插件移植而来，专为纯文本/CLI 环境设计——用符号画树，不依赖图片。

## 0. 开关与触发方式（最重要，先读这个！）

思维树**默认关闭，绝不自动使用**。它由用户的一句话控制：

| 用户说的话 | 效果 |
|-----------|------|
| 「开启思维树」/「打开思维树」/「用思维树」 | 🟢 **开启**：之后遇到复杂问题就用思维树，直到用户说关闭 |
| 「思维树回答：<问题>」/「思维树：<问题>」/「用思维树想一下<问题>」 | 🟢 **单次使用**：只这一次用思维树 |
| 「关闭思维树」/「关掉思维树」/「不用思维树了」 | 🔴 **关闭**：恢复正常回答 |

**执行规则（状态机，按顺序判断）**：
1. 用户没说"思维树"三个字 → **默认关闭，绝不使用本技能**，正常回答即可
2. 用户说了「开启思维树/打开思维树/用思维树」→ 进入**开启状态**：本次会话内**持续生效**，
   之后遇到复杂问题**自动**用思维树，**无需用户每轮重复说「开启」**（说一次，一直开）
3. 用户说了「思维树：问题」→ 只对这一个问题用一次，用完**不改变**开关状态
4. 用户说「关闭思维树/关掉思维树/不用思维树了」→ **关闭状态**：立即失效，恢复正常回答
5. **本次会话结束**（CLI/终端重启、新开会话）→ 自动回到**默认关闭**，下次要从「开启」重新开始
6. 拿不准时，可以反问一句"需要我用思维树深度思考吗？"，听用户指挥

## 0.5 执行模式（一边思考一边动手，默认开启）

思维树不只是"想"，还能"做"——**思考过程中可以直接使用宿主 AI 的一切工具能力**：
读文件、搜索代码、跑测试、执行命令、写文件、git 操作……宿主 AI 会什么，思维树就会什么。
这正是为"修 bug、写代码"类问题设计的：**越难的问题、藏得越深的 bug，分支越多越能挖出来**，
挖出来还要当场修掉。

**默认开启**（用户策略：所有功能默认开启）。用户说「思维树只思考不动手」→ 关闭，只输出分析不动文件。

**修 bug / 写代码场景的流程增强**（在六步流程中嵌入工具操作）：

1. **先侦察再思考**（树干成形后、分支生长前）：
   先读相关文件、搜索关键词、看 git 记录/git log，摸清现状——**分支推理必须基于真实代码，不许空想**
2. **边想边验证**：分支里提出的每一个可疑点，用工具确认（打开对应文件、跑测试或命令复现），
   验证是真 bug 还是误判——验证过的分支才是真思考
3. **直接动手修**：确认根因后直接写文件修复，修复完跑测试/命令验证，确认没改坏别的东西
4. **输出修复报告**：改了哪些文件、为什么改、验证结果（用文字树展示推理过程 + 修复结论）

**执行规则**：
- 需要工具操作时直接操作，不用停下来"请示"——思考与动手交替进行
- 只读操作（读/搜/git log）随时可用；**写操作在修复方案确认后执行**（方案 = 分支收敛出的共识）
- 无法执行工具的环境（纯聊天 AI 如豆包/ChatGPT）：自动降级为「输出修复方案文本」，用户照着改
- 纯分析类问题（决策/对比）不强制动手，正常思考输出即可

## 1. 核心思想

- **多分支探索**：一个问题从 4~5 个独立维度同时推理，而不是一条直线想到底。
- **双重归纳**：每轮结束做两种归纳——①**共识**（所有分支共同指向的结论）②**弱信号**（只有少数分支提到的非常规观点/边界条件）。**弱信号不是噪声，往往是关键盲点**，必须单列展示。
- **动态收敛**：连续两轮共识高度一致（≥90%）就提前收工，不浪费 token。
- **摘要链**：每轮只把 ≤200 字摘要带给下一轮，不传完整历史，省 token 且防跑偏。

## 2. 使用场景（仅在思维树【已开启】时适用）

开关已开启（用户说过「用思维树」）时，遇到以下类型的问题就使用思维树：

| 类型 | 例子 |
|------|------|
| 复杂决策 | 该不该辞职去创业？A 和 B 方案选哪个？ |
| 深度分析 | 这个现象的本质是什么？有哪些被忽略的因素？ |
| 方案设计 | 如何实现某个目标？有哪些路径和风险？ |
| 多角度对比 | 对比两个方案/两个产品/两条路线的优劣 |
| 需要严谨推理的问题 | 需要一步步推导、验证假设的学术/技术问题 |

**开关未开启（默认状态）**：以上问题一律正常回答，不用思维树。

## 3. 数据模型（思维树长什么样）

整个推理过程就是构造一棵树，字段如下：

```
{
  "trunk": "精简后的问题（树干）",
  "rounds": [
    {
      "round": 1,
      "branches": [          // 本轮分支（首轮 4~5 个，后续 3~4 个）
        { "dimension": "维度名", "hypothesis": "假设", "reasoning": "推理", "conclusion": "结论" }
      ],
      "consensus": "本轮共识",
      "weakSignals": ["弱信号1", "弱信号2"]   // 仅 ≤30% 分支提及的观点
    }
  ],
  "stopReason": "converged | maxRounds",
  "summary": "推理摘要",
  "answer": "最终答案"
}
```

## 4. 六步工作流

严格按以下六步执行（每步都要真实思考，不许跳步）：

**第 1 步 · 树根净化**（可选）
用户提供了资料/上下文 → 先清洗为 ≤500 字核心摘要；无资料则跳过。

**第 2 步 · 树干成形**
把原始问题精简为 ≤100 字核心骨架：去情绪、去冗余、去重复，只留问题本质。

**第 3 步 · 分支生长**
基于树干生成分支。**默认每轮 8 个独立分支**（用户可通过自定义配置改，如「3 分支」）。铁律：
- **维度必须按问题领域自主选择**——这是思维树质量的生死线！分支维度必须长自问题本身的具体内容，禁止万能模板套话
- 每个分支是完整的「假设 → 推理 → 结论」三段式
- 精炼紧凑：推理 ≤100 字，结论 ≤80 字
- 分支之间要真正独立，覆盖不同角度，允许互相矛盾

**维度选择示范**（❌ 模板垃圾 vs ✅ 真思考）：

| 问题 | ❌ 万能模板（禁止！） | ✅ 按领域长出的真维度 |
|------|---------------------|----------------------|
| 该不该辞职去创业？ | 技术可行性/成本效益/用户体验 | 财务安全边际/市场验证信号/能力与机会成本/家庭支持与退路 |
| 某数学猜想是否成立？ | 技术可行性/成本效益/用户体验 | 特殊情形验证/反例边界/已知定理关联/计算验证 |
| 选哪种数据库？ | 技术可行性/成本效益/用户体验 | 数据规模与增长/一致性要求/运维成本/团队熟悉度 |
| 为什么销量下滑？ | 技术可行性/成本效益/用户体验 | 渠道流量变化/价格与竞品/产品口碑/用户流失路径 |

**判断标准**：把分支维度拿去套别的领域——如果能套用，就是模板；套不上，才是真思考。

**第 4 步 · 叶片梳理（双重归纳）**
- **共识**：所有分支共同指向的结论（1~2 句）
- **弱信号**：仅 ≤30% 分支出现的非常规观点、边界条件、被忽略的要点。逐条列出

**第 5 步 · 枝叶收敛**
- 比较本轮共识与上一轮共识：核心结论重合度 **≥90%**（无新增关键分歧）→ 收敛停止
- 否则带「共识 + 弱信号」生成下一轮分支（基于共识再发散，验证/深化共识）
- 达到最大轮数（**默认 3 轮**，可 1~10）→ 停止
- **默认必须跑满 3 轮才允许收敛停止**（防止思考太浅，两轮就草草收工）——除非用户自定义轮数

**第 6 步 · 最终输出**
- 渲染**完整文字树**（见第 6 节格式）
- 输出最终答案（结论先行）+ 推理摘要（200~300 字）+ 弱信号记录 + 停止原因
- **修复类问题（执行模式开启时）**：按共识方案直接写文件修复 → 跑测试/命令验证 → 输出修复报告（改了哪些文件/为什么改/验证结果）

## 5. ★ 弱信号检测（思维树的核心特色）

> 原版 ToT（Tree of Thought）论文只做 BFS/DFS 多分支搜索，**弱信号检测是本项目原创增量**——
> 共识代表主流方向，弱信号代表被主流忽略的可能性，它往往藏着决定性盲点。这是思维树区别于普通"多角度分析"的灵魂。

### 什么是弱信号

- **定义**：仅出现在 ≤30% 分支（通常是 1 个分支）中的观点——非常规角度、边界条件、反例、被忽略的要点。
- **为什么重要**：多数分支共同指向的结论=共识（安全但平庸）；少数分支提出的异议=弱信号（危险但关键）。重大决策翻车，几乎都翻在被忽略的弱信号上。
- **例子**：4 个分支都在讨论辞职创业的收益，只有 1 个分支提到"先副业试水更稳"——这就是弱信号，可能是最优解的引子。

### 怎么检测

对每轮全部分支做**逐条比对**，按出现频率分组：
1. 出现在 >30% 分支 → 归入共识方向
2. 出现在 ≤30% 分支（通常是 1 个）→ 候选弱信号
3. 候选弱信号必须是**有实质内容的观点**（新角度/边界条件/反例），重复共识的废话不算

### 怎么用（三件事，缺一不可）

1. **必须单列展示**：弱信号在文字树中用 `⚡` 单独列出，标注出现比例（如 `1/4 分支提及`），不许藏在共识里糊弄过去
2. **必须带进下一轮**：下一轮分支生成时把弱信号作为验证方向（"共识 + 弱信号"一起喂给下一轮），验证它是真信号还是噪声——这是弱信号的深化机制
3. **必须记入最终输出**：最终答案的推理摘要里保留弱信号记录，让用户看到"被多数人忽略但值得警惕的点"

### 诚实红线

- 弱信号**不许编造**：只有真出现于少数分支的观点才能叫弱信号
- 弱信号**不许压制**：即使它和共识矛盾（尤其当它和共识矛盾时！），也要原样展示

## 6. ★ 文字树渲染规范（图像 → 符号）

原版插件用 Canvas 画树形卡片（发散→汇聚→再发散→果实）。**纯文本环境用符号画同一棵树**，效果等价、任何终端都能显示。

### 符号表

| 符号 | 含义 | 对应原版颜色 |
|------|------|--------------|
| 🌳 | 树干（问题） | 紫 #8B5CF6 |
| 🌿 | 分支（推理维度） | 绿 #22C55E |
| 🧡 | 共识（分支收拢汇聚） | 金 #F59E0B |

### 完整树格式（默认，推荐）

树形规则：**树干就是树根**；每轮分支从树干发散（`├──`/`└──`）；每轮共识收拢汇聚；最终答案长在树梢。
格式如下（与 `scripts/render-tree.js` 输出完全一致；**示例为 2 轮简化展示，实际默认 8 分支 × 3 轮**）：

```
🌳 思维树 · 共 2 轮 · 7 个分支 · 已收敛（共识一致性 ≥ 90%）
│
└── 🌳 树干：该不该辞职去创业？
    ├── 🔍 第 1 轮 · 4 个分支
    │   ├── 🌿 财务安全边际
    │   │   假设 → 辞职后收入归零，存款只能支撑 6 个月生活
    │   │   推理 → 创业从启动到稳定盈利通常需要 9~18 个月，6 个月缓冲覆盖不了完整周期
    │   │   结论 → 必须先把缓冲金攒到 18 个月，或保留兼职收入
    │   ├── 🌿 市场验证信号
    │   │   假设 → 需求是真实存在的，不是想象出来的
    │   │   推理 → 目前还没有任何付费客户和订单，行业又处于下行周期，需求只停留在假设阶段
    │   │   结论 → 先拿到 3~5 个付费订单，再考虑全职投入
    │   ├── 🌿 能力与机会成本
    │   │   假设 → 现有技术能力可以支撑创业
    │   │   推理 → 写代码是强项，但创业还需要销售、运营、财税等新能力，且机会成本是放弃稳定涨薪
    │   │   结论 → 能力缺口可以靠合伙人或外包补齐，不是主要障碍
    │   ├── 🌿 家庭支持与退路
    │   │   假设 → 家人支持辞职创业
    │   │   推理 → 如果伴侣或父母反对，心理压力会拖垮决策质量，失败后也没有退路
    │   │   结论 → 需要先沟通并设定止损线：6 个月没起色就回归职场
    │   └── 🧡 第 1 轮共识
    │       共识 → 核心问题不是"要不要创业"，而是"什么时候、以什么方式"——先验证需求，再全职投入
    │       ⚡ 弱信号 → 行业下行周期会放大所有风险，个人能力再强也难逆势（1/4 分支提及）
    ├── 🔍 第 2 轮 · 3 个分支（基于共识再发散）
    │   ├── 🌿 最小验证方案
    │   │   假设 → 用最小成本验证付费意愿
    │   │   推理 → 2 周内做出 MVP 挂到 3 个平台测真实转化率，比任何市场调研都可靠
    │   │   结论 → 本月启动 MVP 测试，以转化率数据决定去留
    │   ├── 🌿 收入断档缓冲
    │   │   假设 → 辞职前后可以保留部分收入来源
    │   │   推理 → 先接外包/兼职过渡，把收入缺口压到最小，降低断档风险
    │   │   结论 → 过渡期 3 个月，边赚边验证
    │   └── 🌿 止损与回归机制
    │       假设 → 创业失败有退路
    │       推理 → 提前与行业保持联系，明确"6 个月无起色即回归"的硬指标，失败成本可控
    │       结论 → 最坏情况是回到原点，不算沉没成本
    └── 💎 最终答案
        结论先行：现在不该直接辞职，先用 2 周做 MVP 验证付费意愿，同时攒够 18 个月缓冲金。
        关键依据：①创业回本周期 9~18 个月，6 个月存款不够；②没有付费客户的需求只是假设；③止损线能把最坏情况控制在"回到原点"。
        风险与不确定性：行业下行周期是最大变量，MVP 转化率是唯一验证手段。
        行动建议：本月启动 MVP + 3 个平台测转化；3 个月后根据数据决定全职时间表。
        📋 推理摘要 → 两轮推理围绕财务缓冲、市场验证、能力缺口、家庭支持四个真实维度展开，共识从"要不要创业"收敛为"先验证再全职"；弱信号提示行业周期风险。最终给出可执行的验证路径。
        ⏹ 停止原因 → 已收敛（共识一致性 ≥ 90%）
```

> 🔑 **看懂这个例子**：分支维度（财务/市场/能力/家庭）是**针对"辞职创业"这个具体问题**长出来的，
> 推理里全是具体数字和事实（9~18 个月回本、6 个月存款、3~5 个订单、2 周 MVP）——
> 这就是"真 AI 思考"，不是任何问题都能套的万能模板。

## 7. Token 优化机制（省钱！）

- **摘要链**：每轮结束生成 ≤200 字摘要，下一轮只传摘要，不传完整历史
- **提前收敛**：跑满默认轮数后，若连续两轮共识一致性 ≥90% 可提前停止（用户自定义更多轮数时尤其有用）
- **默认配置**：8 分支 × 3 轮（用户可自定义）
- **字数红线**：推理 ≤100 字/条、结论 ≤80 字/条、树干 ≤100 字、资料摘要 ≤500 字

## 8. 配置项（默认值 + 用户自定义）

**默认配置**：

| 参数 | 默认 | 范围 | 说明 |
|------|------|------|------|
| 最大轮数 | **3** | 1~10 | 迭代上限，**默认跑满 3 轮** |
| 每轮分支数 | **8** | 2~12 | 每轮发散宽度（首轮/后续轮相同） |
| 收敛阈值 | 0.9 | 0.5~1 | 跑满默认轮数后，共识一致性达到即提前停 |

**用户自定义（一句话生效，无需改文件）**：

| 用户说的话 | 效果 |
|-----------|------|
| 「思维树 3 分支 1 轮」 | 🟢 本次按 3 分支、1 轮执行 |
| 「用思维树 8 分支 3 轮」 | 🟢 本次按 8 分支、3 轮执行 |
| 「以后都用 6 分支 4 轮」 | 🟢 持续生效，直到用户改 |
| 「思维树 收敛阈值 0.8」 | 🟢 调整收敛阈值 |
| 「思维树恢复默认」 | 🟢 回到默认（8 分支 3 轮） |

**解析规则**：从用户指令中提取「数字 + 分支」和「数字 + 轮/轮数」，没提到的部分用默认值。
示例：「思维树 5 轮 6 分支」→ 5 轮、每轮 6 分支；「思维树 4 分支」→ 默认 3 轮、每轮 4 分支。

## 9. 质量红线（踩坑换来的教训）

1. **分支维度按领域选**（生死线）：禁止「技术可行性/成本效益/用户体验」万能模板——数学命题就用数学维度（特殊情形/反例边界/定理关联/计算验证），商业决策就用商业维度（财务/市场/能力/家庭），技术选型就用技术维度（规模/一致性/运维/团队）。**自查方法：把维度拿去套别的领域，套得上就是模板，必须重做**
2. **分支必须结合问题具体内容做真推理**：推理里要有具体数字、事实、机制（如"回本周期 9~18 个月""6 个月存款不够"），不是套话、不是换个说法重复问题
3. **简单问题不要触发思维树**，杀鸡不用牛刀
4. **答案结论先行**：先给 1~2 句直击核心的结论，再补 2~4 条关键依据、风险与不确定性、行动建议，150~300 字，不要花里胡哨
5. **弱信号必须诚实**：只有真出现于少数分支的观点才叫弱信号，不许编造
