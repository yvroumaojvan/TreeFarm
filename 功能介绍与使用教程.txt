一、这是啥？（30 秒看懂）
----------------------------------------------------------------
两个技能，分工明确：

【🌲 思维树 TreeOfThought】管「怎么想」
  一种「把深度思考变成一棵看得见的树」的推理方法：
    问题 = 树干
    推理路径 = 分支
    分支收拢 = 共识（树的新芽）
    少数分支的独到观点 = 弱信号（⚡ 小闪电）
    最终答案 = 长在树梢的果实 💎

  普通 AI 是「一条直线想到底」，思维树是「多个分支同时推理、
  评分剪枝、收拢共识」——像一棵树一样，先发散、再汇聚，多轮迭代直到
  长出答案。v3.0 起：分支要打四维分（证据/相关/新颖/可验证）、低分剪枝、
  死路回溯（💀 标记），搜索过程由 scripts/tree-search.js 管理（无终端则手动模拟）。
  适合：复杂决策、深度分析、多角度对比、修 bug、写代码。

★ 核心特色：弱信号检测（本项目原创增量，v3 算法化）
  多数分支共同指向的 = 共识（安全但平庸）
  只有少数分支提到的 = 弱信号（危险但关键）
  重大决策翻车，几乎都翻在被忽略的弱信号上。
  所以思维树会单独列出弱信号，并带进下一轮验证它是不是真信号。
  （v3：工具按文本相似度聚类 + AI 语义复核，统计出现频率 ≤30% 判定）

【🌳 树场 TreeFarm】管「读哪些、怎么省」
  解决一个大痛点：**AI 读大项目代码时，把不该读的都读了、
  该读的反复读——token 哗哗烧。**
  树场把代码仓库建模成一片森林，让 AI 只读该读的、读一遍就记住：

  代码仓库 = 树场
  ├── 杂草    = 配置/资源/文档 → 只存摘要，命中才展开（省大钱）
  ├── 大树    = 核心代码 → 按任务挑重点读
  ├── 参天大树 = 耦合基因库 → 已确认的依赖关系，复用不重读
  ├── 小鸟    = AI 发现可疑耦合 → 报上去验证
  ├── 小虫子   = 静态分析工具 → 免费验证基因真假（0 token）
  ├── 小树    = 过滤层 → 只给当前文件相关的基因
  └── 垃圾箱  = 熔断器 → AI 反复失误的区域先跳过，最后专项处理

★ 实测战绩：21MB 真实 APK（9187 个 Java 文件）
  全量傻读约 1232 万 tokens → 树场简报约 26 万 → **省 97.9%**
  （📌 对比基准 = AI 傻读全量源码 vs 树场简报，比的是"喂给 AI 的输入量"；
    和"开发者手动查代码"比感知节省约 30~50%。小项目别开树场，直接读更划算）


二、怎么装？（挑一个就行）
----------------------------------------------------------------
【有 Skill 系统的 agent：Claude Code / Qwen Code / Cursor / Windsurf / Gemini CLI 等】

  一键安装（推荐，一次装两个技能）：
    在融合版目录下执行：  bash install.sh
    或装到指定项目：      bash install.sh /你的项目目录

  也可以手动复制两个技能文件夹：
    cp -r tree-of-thought  到  ~/.claude/skills/  （或 .qwen/skills/ 等）
    cp -r tree-farm        到  ~/.claude/skills/  （或 .qwen/skills/ 等）

  装完重启 agent（新开会话）就生效。

【没有 Skill 系统的聊天 AI：ChatGPT / 豆包 / Kimi / DeepSeek 等】

  打开「纯提示词版.md」，把虚线框里的内容整体复制：
  - 有「自定义指令/人设」功能 → 粘贴进去，一劳永逸
  - 没有 → 粘贴到新对话的第一条消息里，后面直接问问题


三、怎么用？（重点！两级触发链开关规则）
----------------------------------------------------------------
两个技能【默认全部关闭，绝不自动触发】。开关是两级状态机：

  ┌────────────────────────────────────────────────────┐
  │ 你什么都不说          → 全关，AI 正常回答          │
  │ 你说「开启思维树」     → 🟢 思维树开启！一直生效    │
  │    （/打开思维树/用思维树 都行）                    │
  │    └→ 只说这句 = 只用思维树，树场保持关闭          │
  │ 再说「开启深度思考模式」→ 🌳 树场也开启            │
  │    （等价词：开启深度代码分析/开启深度代码阅读）    │
  │ 你说「思维树：问题」   → 只对这一个问题用一次思维树  │
  │ 你说「关闭思维树」     → 🔴 思维树关闭              │
  │ 你说「关闭深度思考模式」→ 🌳 树场关闭（思维树保持）  │
  │ 树场模式下「关闭 LLM」 → 📵 停用自动分析（默认开）  │
  │ 重启 / 新开会话       → 全部自动回到默认关闭        │
  └────────────────────────────────────────────────────┘

★ 关键：说一次「开启思维树」，之后【一直生效】——
  遇到复杂问题 AI 会自动用思维树，不用每轮重复说！
  想两个功能都开，就按顺序说两句话。想关掉就逐级说「关闭」。

使用姿势：

  ✅ 只用思维树：发「开启思维树」，然后正常聊天
  ✅ 两个全开：先「开启思维树」，再「开启深度思考模式」
  ✅ 单次模式：直接发「思维树：该不该辞职去创业？」
  ✅ 关掉：发「关闭思维树」


四、用起来长什么样？（效果预览）
----------------------------------------------------------------
【思维树】开启后，遇到复杂问题时 AI 会画出一棵符号树：

🌳 思维树 · 共 2 轮 · 7 个分支 · 已收敛（共识一致性 ≥ 90%）
│
└── 🌳 树干：该不该辞职去创业？
    ├── 🔍 第 1 轮 · 4 个分支
    │   ├── 🌿 财务安全边际
    │   │   假设 → 辞职后收入归零，存款只能支撑 6 个月生活
    │   │   推理 → 创业回本通常要 9~18 个月，6 个月缓冲不够
    │   │   结论 → 先把缓冲金攒到 18 个月，或保留兼职收入
    │   ├── 🌿 市场验证信号
    │   │   假设 → 需求是真实存在的
    │   │   推理 → 目前还没有任何付费客户和订单
    │   │   结论 → 先拿到 3~5 个付费订单再全职投入
    │   ├── 🌿 能力与机会成本
    │   │   结论 → 能力缺口可以靠合伙人补齐，不是主要障碍
    │   ├── 🌿 家庭支持与退路
    │   │   结论 → 先沟通并设定止损线：6 个月没起色就回归
    │   └── 🧡 第 1 轮共识
    │       共识 → 核心问题不是"要不要创业"，
    │               而是"什么时候、以什么方式"——先验证再全职
    │       ⚡ 弱信号 → 行业下行周期会放大所有风险（1/4 分支提及）
    ├── 🔍 第 2 轮 · 3 个分支（基于共识再发散）
    │   ├── 🌿 最小验证方案 → 2 周 MVP 挂 3 个平台测转化率
    │   ├── 🌿 收入断档缓冲 → 过渡期 3 个月，边赚边验证
    │   └── 🌿 止损与回归机制 → 6 个月无起色即回归，成本可控
    └── 💎 最终答案
        结论先行：现在不该直接辞职，先用 2 周做 MVP 验证
        付费意愿，同时攒够 18 个月缓冲金。
        📋 推理摘要 → ……
        ⏹ 停止原因 → 已收敛（共识一致性 ≥ 90%）

符号对照：🌳树干 🌿分支 🧡共识 ⚡弱信号 💎答案 📋摘要 ⏹停止

【树场】「开启深度思考模式」后分析大项目，AI 会先出简报：

  python3 tree-farm/scripts/tree_farm.py <项目> --brief
  → 输出「AI 工作简报」：大树清单 + 每文件正/反向基因 + 杂草索引
  → AI 读简报挑重点，不盲目全读项目

  完整命令集（v3.2）：
  python3 tree_farm.py <项目>                        # 树场体检（建库/复用/腐肉检测）
  python3 tree_farm.py <项目> --brief                # AI 工作简报（省 token 核心）
  python3 tree_farm.py <项目> --bird <源> <目标>     # 报小鸟（强耦合，小虫子验证）
  python3 tree_farm.py <项目> --bird-weak <源> <目标>  # 报小鸟（弱耦合，双分支确认）
  python3 tree_farm.py <项目> --analyze <文件>       # LLM 自动找小鸟（自动找卡）
  python3 tree_farm.py <项目> --search <关键词>      # 语义搜索（跨语言）
  python3 tree_farm.py <项目> --symbols <文件>       # 看文件符号（函数/类名）
  python3 tree_farm.py <项目> --llm on/off/status    # LLM 开关（默认开启）
  python3 tree_farm.py <项目> --trash                # 垃圾箱
  python3 tree_farm.py <项目> --next-round           # 新一轮
  python3 tree_farm.py <项目> --converge             # 收敛检查
  python3 tree_farm.py <项目> --fix <文件>           # 修复协议（需用户同意）
  # 代码分析（v3.1，中文/英文等价）：
  python3 tree_farm.py <项目> --dead-code            # 死代码检测
  python3 tree_farm.py <项目> --circular-deps        # 循环依赖检测
  python3 tree_farm.py <项目> --impact <文件>        # 影响分析（改这里会影响哪）
  python3 tree_farm.py <项目> --complexity           # 圈复杂度
  python3 tree_farm.py <项目> --architecture         # 架构分层识别
  python3 tree_farm.py <项目> 分析 死代码            # 中文命令（等价）
  # v3.2 新选项：
  python3 tree_farm.py <项目> --json                 # 体检/简报输出机器可读 JSON
  python3 tree_farm.py <项目> --quiet                # 关闭扫描进度条
  # 配置文件（.treefarm.toml 或 .treefarm.json，放项目根目录）：
  #   [scan]
  #   ignore = ["**/vendor/**", "*.min.js"]     ← gitignore 风格忽略规则
  #   ignore_dirs = ["build"]                   ← 整目录跳过

  LLM 自动找卡（小白模式，啥也不用配）：
  引擎自动按顺序找：项目/.treefarm.toml → 项目/.treefarm.json → ~/.treefarm.toml → ~/.treefarm.json → 环境变量
  （支持 TREEFARM_ / OPENAI / DASHSCOPE / DEEPSEEK / MOONSHOT / ARK）
  找不到就 dry-run 预览（不烧钱）。国内建议 DeepSeek/通义：
  echo '{"api_key":"sk-你的key","base_url":"https://api.deepseek.com/v1","model":"deepseek-chat"}' > .treefarm.json

  【配置文件完整参考】（v3.2/v3.3，放项目根目录，.treefarm.toml 优先于 .treefarm.json）

  python3 tree_farm.py <项目> --graph               # 调用图（Mermaid，可粘贴渲染）
  python3 tree_farm.py <项目> --graph <文件>        # 某文件的符号级调用图
  python3 tree_farm.py <项目> --duplicates          # 重复代码检测（相似度≥0.6）
  python3 tree_farm.py <项目> 分析 调用图           # 中文等价
  python3 tree_farm.py <项目> 分析 重复代码         # 中文等价

  # v3.4 分析深度：Java 函数级（APK 逆向/安卓项目福音）
  函数级调用分析覆盖：Python（AST 精确）+ JS/TS + Java（零依赖手写解析器）
  Java 支持的语法：方法/构造器/接口抽象方法、泛型（class A<T> extends Base<T>）、
  extends/implements 多接口、interface 多继承、enum/record；

五、进阶玩法（一句话自定义）
----------------------------------------------------------------
  「思维树 3 分支 1 轮」      → 本次按 3 分支、1 轮执行
  「用思维树 8 分支 3 轮」    → 本次 8 分支、3 轮（默认值）
  「以后都用 6 分支 4 轮」    → 持续生效，直到改
  「思维树 收敛阈值 0.8」     → 调整收敛阈值
  「思维树恢复默认」          → 回到默认（8 分支 3 轮）

  默认配置：8 分支 × 3 轮，收敛阈值 0.9。
  跑满轮数后如果连续两轮共识一致（≥90%）可以提前收工，省 token。

  执行模式默认开启：思维树思考时可以直接调用 agent 的工具
  （读代码、跑测试、写文件、修 bug）——思考与动手交替进行。
  说「思维树只思考不动手」→ 关闭执行模式。


六、树场省 token 原理 + 实测数据
----------------------------------------------------------------
省 token 四板斧：
1. 别读不重要的：杂草只存摘要 → 省下配置/资源/文档的全文
2. 别重复读：基因库记住依赖关系 → 第二次排查直接引用
3. 别读无关的：小树过滤 → 只看当前文件相关的耦合
4. 免费当质检：小虫子用静态工具验证，0 token 且 100% 确定

实测数据（2026-08-08）：
★ 真实 APK（自动点击器 2.0.12.31，21MB → 9187 个 Java 文件/47MB 源码）
   AI 傻读全量: 约 1,232.6 万 tokens
   树场简报:    约 26.2 万 tokens
   第一轮节省:  ★ 97.9% ★   基因库 57,919 条（建库仅 2 分钟）

★ 规模模拟曲线（每文件约 2000 字符）
   50 文件 → 省 95.6% | 100 文件 → 省 96.3% | 500+ 文件 → 省 96.9%

★ 诚实边界：小项目实测（8 小文件 188 tokens）简报反而贵 112.8%
   → 固定开销没摊薄。树场为「大项目 + 多轮排查」而生，
     小项目/一次性任务请直接读，别开树场。


七、质量红线（思维树的灵魂，AI 必须遵守）
----------------------------------------------------------------
1. 分支维度必须按问题领域选——数学题用数学维度、
   商业题用商业维度，禁止「技术可行性/成本效益/用户体验」
   万能模板（套得上别的领域就是模板，必须重做）
2. 分支推理要有具体数字和事实，不许说套话
3. 弱信号必须真实：只有少数分支真提到的观点才算数，
   不许编造、不许藏起来
4. 用户没提"思维树" → 绝不用，正常回答（这是开关！）


八、常见问题
----------------------------------------------------------------
Q：装了没反应？
A：检查文件夹名必须是 tree-of-thought / tree-farm（与 SKILL.md 里
   name 一致），SKILL.md 在文件夹根目录，然后重启 agent 会话。

Q：两个技能会打架吗？
A：不会。思维树管「怎么想」，树场管「读哪些、怎么省」，
   各自独立开关、独立状态机，触发链严格有序。

Q：只想用一个技能怎么办？
A：随便。只装 tree-of-thought/ 或只装 tree-farm/ 都能独立工作；
   融合版是"全都要"的选择，不是强制绑定。

Q：思维树输出太长？
A：说「用紧凑模式」或「分支只留结论」，树会短一半。

Q：怎么最省 token？
A：思维树默认 8 分支 × 3 轮带摘要链优化（每轮只传 ≤200 字），
   觉得贵就手动调小：「思维树 4 分支 2 轮」。
   树场只在大项目 + 多轮排查时开，小项目直接读。
